## 1. Introduction

### 1.1 Purpose
This document specifies the software requirements for MBU RouteX, a university transportation management and tracking web application for Mohan Babu University.

### 1.2 Scope
MBU RouteX provides role-based transportation services to students, drivers, and management personnel. The system covers bus tracking, complaint management, QR attendance, emergency access, and transport operations. See `00-master/PROJECT_SCOPE.md` for full scope definition.

### 1.3 Definitions

| Term | Definition |
|---|---|
| MBU | Mohan Babu University |
| ROLE_STUDENT | Authenticated student user |
| ROLE_DRIVER | Authenticated driver user |
| ROLE_MANAGEMENT | Authenticated management user |
| QR Code | Student attendance QR generated by the system |

## 2. Overall Description

### 2.1 Product Perspective
MBU RouteX is a standalone modular monolith web application. It interacts with a MySQL database and serves HTML/CSS/JS frontend pages via Spring Boot.

### 2.2 Product Functions

**Public interface:**
- Display MBU RouteX homepage
- Role selection (Student / Driver / Management)
- Role-based login

**Student functions:**
- View assigned bus information
- Track bus in real time
- Submit complaints
- Access emergency contacts
- Display personal QR code for attendance

**Driver functions:**
- View and update bus status
- View service details
- Report bus issues
- View daily and trip schedules
- Access emergency contacts

**Management functions:**
- View and manage fleet (bus details)
- Monitor live trips
- Review and manage all complaints
- Track maintenance records
- Generate reports
- View student overview

### 2.3 User Classes

| User Class | Description |
|---|---|
| Student | Enrolled MBU student using university transport |
| Driver | University bus driver |
| Management | Transport department administrator |
| System Admin | Technical administrator (TO BE DEFINED) |

### 2.4 Operating Environment
- Server: Java 17+, Spring Boot, MySQL
- Client: Modern web browser (Chrome, Firefox, Edge, Safari)
- Network: University network or internet-connected

### 2.5 Design Constraints
- Locked visual design — no redesign permitted
- Modular monolith architecture for initial release
- MySQL as the only supported database initially
- Role access strictly enforced by Spring Security

### 2.6 Assumptions and Dependencies
- MySQL server is available and configured
- Users have access to a modern browser
- University provides campus photograph for hero image
- QR code scanning hardware or camera access is available for attendance
